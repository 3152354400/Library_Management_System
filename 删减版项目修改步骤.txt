删减版图书馆管理系统项目修改步骤

一、总体修改原则

1. 不要一次性全项目重构
建议按照以下顺序逐步修改：
数据库层优先 -> 后端模型与 DTO -> 后端 Repository / Service -> 后端 Controller -> 前端路由 -> 前端页面与菜单 -> 文档同步。
每一步只处理一个模块或一组强相关文件，避免一次修改大量文件。

2. 每次修改控制范围
建议每次只改：
- 1 个数据库脚本文件；或
- 1 个后端模块；或
- 1 个前端模块；或
- 1 个文档章节。
不要一次同时改数据库、后端、前端和文档。

3. 先备份再删减
在实际执行前建议先建立删减版分支或备份目录，例如：
- database_original_backup/
- backend_original_backup/
- frontend_original_backup/
如果是 Git 项目，应先新建分支：git checkout -b simplify-three-person-version。
如果当前不是 Git 仓库，则建议复制一份项目目录作为备份。

4. 先禁用，再删除
对于复杂模块，不建议第一步直接删除所有文件。推荐流程是：
先从路由/菜单/API 注册中移除 -> 确认系统可启动 -> 再删除无引用代码 -> 最后清理数据库表和脚本。
这样可以避免一次删除过多导致难以定位错误。

三、阶段二：数据库脚本修改步骤

数据库层建议优先修改，因为后端和前端都依赖数据库结构。

步骤 5：新建删减版数据库脚本
不要直接覆盖原始 schema.sql。
建议先新建一个新的数据库脚本，例如：database/schema_three_person.sql。
该脚本只包含 15 张最终保留表。
好处：
- 不破坏原始十人版设计
- 方便对比
- 方便答辩展示
- 方便失败后回滚

步骤 6：按依赖顺序编写建表语句
建表顺序应为：
1. Reader
2. Librarian
3. Building
4. Bookshelf
5. BookInfo
6. Book
7. Category
8. Book_Classify
9. BorrowRecord
10. Booklist
11. Booklist_Book
12. Collect
13. Comment_Table
14. Report
15. Announcement
注意：
- 被外键引用的表必须先创建。
- 自引用表 Category 可直接创建，但插入数据时父分类需先插入。
- 多对多关系表放在两个主表之后创建。

步骤 7：统一主键类型
建议统一使用：INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY。
适用于：
ReaderID、LibrarianID、BuildingID、ShelfID、BookID、CategoryID、BorrowRecordID、BooklistID、CommentID、ReportID、AnnouncementID。
ISBN 继续使用 VARCHAR2(20) 作为 BookInfo 的主键。
这样可以减少类型不一致导致的外键错误。

步骤 8：添加必要约束
每张表需要保留基本约束：
- 主键约束
- 外键约束
- 唯一约束
- CHECK 约束
- NOT NULL 约束
- 默认值约束
重点约束包括：
- Reader.CreditScore BETWEEN 0 AND 100
- Reader.AccountStatus IN ('正常', '冻结')
- Book.Status IN ('正常', '借出', '下架', '遗失')
- BorrowRecord.Status IN ('借阅中', '已归还', '逾期', '遗失')
- Comment_Table.Rating BETWEEN 1 AND 5
- Report.Status IN ('待处理', '驳回', '处理完成')
- Announcement.Status IN ('发布中', '已撤回')

步骤 9：添加核心索引
先添加少量必要索引即可，不要一次性添加太多。
建议保留：
CREATE INDEX idx_book_isbn ON Book(ISBN);
CREATE INDEX idx_book_status ON Book(Status);
CREATE INDEX idx_borrow_reader ON BorrowRecord(ReaderID);
CREATE INDEX idx_borrow_book ON BorrowRecord(BookID);
CREATE INDEX idx_borrow_status ON BorrowRecord(Status);
CREATE INDEX idx_comment_isbn ON Comment_Table(ISBN);
CREATE INDEX idx_report_status ON Report(Status);
CREATE INDEX idx_booklist_creator ON Booklist(CreatorID);
CREATE INDEX idx_collect_reader ON Collect(ReaderID);

步骤 10：添加数据库函数
优先添加一个函数即可：calculate_overdue_fine。
用于计算逾期罚款。
功能：
- 根据 DueTime 和 ReturnTime 计算逾期天数
- 每逾期一天罚款 0.5 元
- 未逾期返回 0

步骤 11：添加核心触发器
建议只保留两个库存相关触发器：
1. trg_book_after_insert
2. trg_book_status_update
用途：
- 新增实体书后同步总库存和可借库存
- 实体书状态变化后同步可借库存
这样既体现数据库业务逻辑，又不会太复杂。

步骤 12：添加核心存储过程
建议分批添加，不要一次写太多。
第一批：
- borrow_book
- return_book
第二批：
- process_overdue_records
- handle_report
每次添加一个存储过程后，立即单独测试，避免多个过程同时报错无法定位。

步骤 13：添加核心视图
建议保留三个视图：
1. V_BookDetail
2. V_ReaderBorrowDetail
3. V_PendingReport
分别服务于：
- 图书详情查询
- 读者借阅记录查询
- 管理员举报处理

步骤 14：准备精简测试数据

十、每一步完成后的检查标准

1. 数据库结构：15 张表可全部创建成功。
2. 数据库约束：主键、外键、唯一约束、CHECK 约束无冲突。
3. 函数：逾期罚款计算结果正确。
4. 触发器：新增实体书和借还书时库存变化正确。
5. 存储过程：借书、还书、逾期处理、举报处理可执行。
6. 视图：图书详情、借阅详情、待处理举报可查询。
7. 后端：dotnet build 成功。
8. Swagger：只展示删减后的核心接口。
9. 前端：npm run build 成功。
10. 页面：不再出现座位预约、采购分析、复杂推荐等入口。
11. 文档：表数量、功能点、E-R 图、关系图与删减版一致。
