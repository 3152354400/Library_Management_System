# 变更说明

本文档记录本分支相对 dev 分支的部署适配与问题修复。前端代码未做改动。

## 一、数据库

dev 分支的数据库脚本存在引用不完整的问题（部分建表脚本缺依赖对象），部署时按实际运行补齐：

- 精简版（15 表）阶段补齐了代码仍引用的对象：`Fine`、`BookLossReport`、`BookFavorite`、`Log`、`V_BookAdmin_Info`，脚本见 `deploy/fix_missing_objects.sql`。
- 完整版升级：在 15 表基础上增量补齐 dev 完整功能所需的全部对象（只增不改，可回滚）：

| 类别 | 内容 |
|---|---|
| 新表（11 张） | Seat、StudyRoom、Reserve_Room、Reserve_Seat、RenewRecord、FinePayment、OperationLog、ReserveBook、RecommendPurchase、Notification、PurchaseLog |
| 加列 | Fine（FineType / DueDate / PayTime）、Book_Classify（RelationNote） |
| 视图（6 个） | V_Seat_Status、V_MyReservations、V_BookRank_By_BorrowCount、V_BookRank_By_BorrowDuration、V_BookRank_By_InstanceBorrow、book_list_rank_view |
| 函数（1 个） | get_recommendations |
| 存储过程（6 个） | sp_renew_book、sp_reserve_book、sp_cancel_reserve、sp_recommend_purchase、sp_handle_recommend、sp_pay_fine |
| 触发器（4 个） | 还书生成罚款、预约到期、通知到期、评论级联删除 |
| 序列（10 个） | seq_barcode 等 |

升级脚本：`deploy/sql/upgrade_full_1.sql`（表 / 列 / 序列 / 示例数据）、`deploy/sql/upgrade_full_2.sql`（视图 / 函数 / 过程 / 触发器），按顺序执行。

## 三、部署配置

| 组件 | 配置 |
|---|---|
| Oracle 19c | Docker 容器，端口 1521 仅绑定本机，数据卷持久化 |
| 后端 | systemd 服务，.NET 8，监听 5000 |
| Redis | 本机 6379，仅本机访问 |
| Nginx | 80 端口托管前端，`/api` 与 `/api/ws` 反向代理到 5000 |

真实连接串、Redis 密码、JWT Secret 等敏感配置不提交仓库，参考 `backend/appsettings.Production.example.json` 创建本地配置文件。

## 四、已知限制

- Oracle 官方 Docker 镜像在部分网络环境下拉取失败，需本地构建（构建参数 `SLIMMING=false`）。
- 数据库脚本中的中文默认值需在 `NLS_LANG=AMERICAN_AMERICA.AL32UTF8` 环境下执行。
